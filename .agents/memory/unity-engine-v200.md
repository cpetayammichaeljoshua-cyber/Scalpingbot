## Rule
All positive-score additions must go through `self._wr_dampen(pts)` before landing on `quality_score`.
Compute dampened value into a local variable first — use that same local for both `quality_score +=` and the log f-string to avoid double-call drift.

**Why:** _wr_dampen is WR-dependent; calling it twice in the same expression (once for score, once for log) is technically safe but can diverge if WR changes between calls in a concurrent context, and produces confusing log entries.

**How to apply:** `_pts = self._wr_dampen(RAW_CONST); quality_score += _pts; logger.debug(f"→ +{_pts:.2f}pts (raw={RAW_CONST} WR-dampened)")`

After dampening, a conditional suffix `[applied=X raw=Y WR-dampened]` is appended when the applied value differs from raw by >0.01pts, making telemetry accurate during low-WR regimes.
